AmebaD (RTL8721D) was upgraded from the SDK's bundled FreeRTOS v10.2.0 to the **upstream FreeRTOS-Kernel V10.6.2** shared with Bouffalo (`component/thirdparty/freertos-kernel`, kernel-only, upstream CMake `add_subdirectory` + `FREERTOS_PORT` + `freertos_config` + `FREERTOS_HEAP`). The old `component/thirdparty/freertos_amebad` submodule was deleted. `component/amebad/freertos_port/CMakeLists.txt` rewrites to chip-select the port + `add_library(FreeRTOS ALIAS freertos_kernel)` so consumers are unchanged.

**THE port-selection trap (cost a HardFault debug):**
- **KM4 (HP, Cortex-M33)** → `GCC_ARM_CM33_NTZ_NONSECURE`. Works: its `vStartFirstTask` resets MSP from `VTOR[0]`, and KM4 image2's vector-table word[0] IS a valid stack top (the SDK HP port did the same VTOR/MSP reset).
- **KM0 (LP, Cortex-M23)** → MUST use **`GCC_ARM_CM0`** (ARMv6-M), NOT the native `GCC_ARM_CM23_NTZ_NONSECURE`. The CM23_NTZ `vStartFirstTask` also resets MSP from `VTOR[0]`, but **KM0 image2's `VTOR[0]` is not a valid stack top** → `vTaskStartScheduler()` HardFaults on the start-scheduler SVC. Symptom in the LOG: clean boot + `[KM4] FreeRTOS kernel V10.6.2` banner, then `Hard Fault Error!!!!` with `xPSR=0x6100000b` (low byte 0x0b = ISR 11 = SVCall) and `PC` in the KM0 XIP range (`0xc00xxxx`; KM4 XIP is `0xe00xxxx`). The upstream `ARM_CM0` port comments "The MSP stack is not reset ... there is no vector table offset register" and never touches MSP — exactly what the SDK's `RTL8721D_LP` port (an ARM_CM0 derivative) did. Running the ARMv6-M port on the M23 is fine (backward-compatible) and matches the SDK. Lesson: **match the SDK's port *family*, not the core's nominal architecture.**

**Wiring details that are easy to get wrong:**
- SDK headers drag FreeRTOS into nearly every TU (`ameba_soc.h` → `freertos_pmu.h` → `#include "FreeRTOS.h"`), so components that don't link the kernel (ram_common, ram_hp, usrcfg, ...) still need `FreeRTOS.h` + `portmacro.h`. So `component/amebad/sdk_includes/CMakeLists.txt` carries the **new kernel** `include/` + the per-core port dir (`GCC/ARM_CM0` for km0, `GCC/ARM_CM33_NTZ/non_secure` for km4) — NOT the old `freertos_v10.2.0` paths. The portmacro path here MUST match the FREERTOS_PORT chosen in `freertos/CMakeLists.txt`.
- FreeRTOSConfig.h override at the shared `component/freertos_config/FreeRTOSConfig.h`: `#include_next "FreeRTOSConfig.h"` to the SDK inc_lp/inc_hp base, then only `#undef`/`#define configUSE_TICKLESS_IDLE 0` (decouples from SDK PMU sleep externs `vPortSuppressTicksAndSleep`/`freertos_pre/post_sleep_processing`). The override dir is placed on `amebad_sdk_includes` FIRST (before inc_lp/inc_hp) so all TUs see one consistent config; `freertos_config` just links `amebad_sdk_includes`. **Do NOT add `configTICK_TYPE_WIDTH_IN_BITS`** — V10.6.2 `FreeRTOS.h` errors if it AND the SDK's `configUSE_16_BIT_TICKS 0` are both defined; the backward-compat path already gives 32-bit ticks. `configSUPPORT_STATIC_ALLOCATION` is not needed (dynamic alloc default covers idle/timer).
- The SDK kept `vApplicationIdleHook`/`vApplicationStackOverflowHook`/`vApplicationMallocFailedHook` in its `port.c`; the upstream ARM ports don't, so they now live in `component/amebad/freertos_port/freertos_hooks.c` (gated on the matching config macros; KM0 inc_lp has malloc-hook 0, KM4 inc_hp has it 1). The two existing glue files (`freertos_backtrace_ext.c`, `freertos_heap5_config.c`) were vendored out of `platform/ameba-rtos-d/component/os/freertos/` into `component/amebad/freertos_port/` (one shared copy, compiled per-ABI by `amebad_freertos_glue_km0`/`_km4`, mirroring `common_ld_script/`).
- The upstream kernel CMake compiles `-Wall -Wextra -Wpedantic -Werror`; the AmebaD config (empty `configASSERT`, etc.) trips it, so `freertos/CMakeLists.txt` demotes `-Werror` on `freertos_kernel`/`freertos_kernel_port`.

Build/verify: `cmake -S . -B build/km0 -DCMAKE_TOOLCHAIN_FILE=cmake/amebad-km0.cmake` (toolchain auto-found at `toolchain/asdk-10.3.1-4354/...`), build `target_img2_km0`; same for km4; then `python3 component/amebad/image_tool/build_image_all.py`. Flash + boot validated: banner prints `FreeRTOS kernel V10.6.2`, `help` is interactive (`#` prompt + `[MEM] After do cmd, available heap ...`). Boot-rodata trap + LOG baud in [[amebad-boot-rodata-xip-trap]]; flash via [[reference_amebad_imagetool]].
